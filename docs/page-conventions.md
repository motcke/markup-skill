# Page and panel conventions

How `assets/plan.css`, `assets/plan.js` and `server.mjs` behave, folded from the user's feedback (25–28/08/2026).
Read this **only when changing those files** — composing a page needs `references/` alone.
Keep every convention here when touching the code; each one was asked for explicitly.

## Page

| Area | Convention |
| --- | --- |
| Layout | Full viewport width, small side margins. No centered max-width gutter. **The text takes the whole free width; cards never narrow it** (user, 29/09). Anchored mode reserves only the docked list (`--float-col` = the panel's width + a gap); panel mode reserves the open panel's column (`--panel-col`) when the text keeps ≥500px. Cards, and the open compose box, float over the text next to their anchors, and a card that covers something is the user's to fold (▾), hide (−) or shrink (corner handle). A reserved cards column beside the text (28/09) narrowed every page with a comment by 360px and hid the table of contents; the user asked for it to go. Tables re-measure and KPI rows re-balance whenever the text column changes width (the docked list opening or folding) |
| Narrow windows (28/09, 29/09) | Below 1181px the agent status keeps one word ("No agent" / "Listening", `data-short`) instead of the sentence, never a bare dot. Below 600px (phones) the top bar scrolls away with the page (`position: static`, `--top-h` 0), drops its title (the `<h1>` right under it says the same), and a kanban stacks its columns. Above 900px the top-bar actions sit at the inline-end (29/09: packed against the title they left half the bar empty). Anchored mode needs ≥1060px; below that the page runs panel mode without touching the stored choice (`storedFloat` vs the effective `floatMode`) and hides the mode pair. Below 900px the top bar wraps into rows, the context meter and the mode pair hide, and the panel is a bottom sheet (62vh). `--top-h` follows the measured top bar |
| Versions | `publish --note-file` labels each version with what changed. Sections tagged "חדש" (green) or "עודכן" (blue) on the page carry the same color and a dot in the table of contents until "ראיתי" |
| Charts | Neutral default palette; meaning colors only via `tones` / `tone`. Animation off (screenshots), font from the page `--font`, ticks never rotate, grid faint. A chart with one dataset has no legend: it named what the heading and the axis already say, and colored per bar by `tones` it showed the first bar's color as the series color (29/09); `options.plugins.legend.display: true` brings it back. Lines curve monotone (`cubicInterpolationMode`), never overshooting the points |
| Tables | Every table with a header sorts on every column, three-state (asc → desc → original order); `data-sort="off"` opts out. Sort values ignore our own marks (rank, delta, sparkline). Decorations are declarative (`data-heat`, `data-bar`, `data-delta`, `data-rank`, `td.tl`, `tr.pick`, `data-spark`); colors computed in `plan.js`, legend appended after the table. Filter box above 12 rows, sticky header above 8. `.table-wrap` scrolls only when the table is really wider (measured), otherwise the sticky header would break. Sparklines follow `data-spark-good="down"` (cell or column) like deltas follow `data-delta-good`, so a falling failure count is green in both (29/09). Review 29/09: the light red→green scale uses the 200 shades (the 300s shouted over the page); a heat legend always runs low → high, and `desc` reverses its colors, not its numbers; headers are keyboard-reachable (`tabindex`, Enter / Space sort, `aria-sort`); a box that scrolls sideways (`.table-wrap.scrolls`, a wide diagram) fades on the side that has more (`watchScroll` sets physical `fade-l` / `fade-r`, since RTL scrolls the other way) and takes `tabindex="0"` while it scrolls, so the keyboard can reach its hidden part |
| Code | `<pre>` gets a copy button; `highlight.js` (vendored common build) highlights `language-*` blocks, auto-detects only at relevance ≥ 6 |
| Context meter (segments) | H#65 (30/08), H#75 (31/08): the meter reads only the plan's own session (never "the newest transcript of the project" — full separation between conversations, like `--session` everywhere else; hidden when that session has no transcript). `/ctx.segments` splits the bar by version — one `<i>` per version (usage of the last assistant call before the history file's mtime, minus the previous version), darker as versions go, a 2px red `reset` slice where the context shrank (compaction), and a last slice "מאז הגרסה האחרונה". One instant tooltip for the whole meter (CSS `:hover`, no `title` delay — the bar is too thin to hover a slice for seconds): every version top to bottom with its swatch (same color and opacity as the bar slice) a filled length (no track, not a progress bar) relative to the largest version row and the number alone (no words), then one gray row "נשאר" on the same scale (clipped at full width; it is not part of the max — the whole-context share is already in the top bar), then a total row and a muted footer (model · session · updated). No per-slice titles, and no version notes (they are in the dropdown). Measures how much the whole conversation grew between versions, not what the page cost (user feedback 30/08) |
| Context meter | Top bar, right next to the title (inline-start side), shows how full the serving agent's context is (`הקשר NN% · 150k / 1M`, amber from 60%, red from 85%). `GET /<dir>/api/ctx` reads the last assistant usage (input + cache creation + cache read) from the project's newest transcript under `~/.claude/projects/`, preferring the plan's own session while it is the newest; `reply` stamps `meta.sessionId` with the answering session. Window size 1M when the settings model carries `[1m]`, else 200k. Polled every 10s; hidden when no transcript |
| Agent status | One element in the top bar (`#agentStatus`, H#52, 28/08) replaces the dot, the "סיימתי" button and the chip. A state machine over `/state` (`listening`, `listeningSince`, `wake`) and `/ctx` (`ownActiveAt`, mtime of the plan session's transcript): `none` gray "No agent listening · last seen HH:MM" with a **neutral** (not primary) button "Copy command for the agent" (H#68, 30/08; relabelled 28/09: a blue "wake" button that wakes nobody misled every new user): a press records the call, copies `/markup comments <dir>` (`/state.wakeCmd`) to the clipboard, and shows a browser notification when permitted; the `nobody` chip that follows is gray, "Saved. Paste the command into the agent's session", with a "Copy command" button — information, not an error → `listening` green dot + button "הער את הסוכן" + "מאזין מאז HH:MM" → `busy` (transcript written in the last 30s) spinner "הסוכן פעיל" + button labelled "שלח לתור הסוכן" (not "הער את הסוכן"); "לחיצה נכנסת לתור ותימסר בסיום התור" is the hover title of the button and the widget, not visible text (user, 30/08: the queueing note belongs to the button, not to the status) → `confirm` (pressed with unanswered questions) "N שאלות לא נענו · [שלח בכל זאת] [המשך לענות] ✕", its dot green only while someone listens (`.off`, 29/09: a green dot with nobody there said the opposite of the truth) → `sent` amber with timer (`late` red after 60s) → `picked` / `working` blue (3 minutes with no transcript activity after either → `stuck` red "אין סימן חיים מהסוכן מאז HH:MM" + "שלח שוב" — the harness died on the way: disconnect, crash, a waiting approval; #7 30/08) → `done` green "הסוכן סיים ב-HH:MM" for 5 minutes, with the wake button while a listener exists, and cancelled entirely by any open comment newer than the done stamp (a new comment reopens the round; #7 30/08). ✕ cancels a pending call (`DELETE /api/wake`) or the confirm. `publish` still prints `listening` and warns when false |
| Questions | Clarifying questions are `.q` blocks: one option per line, radio (`single`) or checkbox (`multi`), the recommended option first with the `q-rec` pill, a "דלג" option, free text as a growing `textarea` with no length limit, and attachments (paperclip / paste) saved under `assets/` on the answer. A pick is saved at once to `answers.json` and shown by `comments` under "Picks in question blocks" (new since last read; `--all` for everything; `attachment:` lines like a message's). Consecutive `.q` blocks become a guide (H#56, reshaped H#57 30/08): a bounded box (`.q-guide`) with a heading + "N / M נענו" counter, a step strip (`.q-steps`: numbered circles joined by a line, title under each, green ✓ when answered, accent when active), one question shown, and prev / next side by side under the question (next is `btn primary` = next unanswered; at the end of the box `jumpToUnanswered` takes over, so it crosses into the next box). `data-cat` splits a run into one box per category ("שאלות לגבי <cat>", numbered from 1) — no category tabs. Keys `1`–`9` pick and `Enter` moves on (only inside the guide, never while typing). The step strip never wraps (`nowrap`, steps share the width, titles cut with an ellipsis): wrapped, a step's line hung into the empty row start (29/09). The key hint hides on touch screens (`hover: none`). Print: steps and nav hidden, every question shown. The top bar shows "שאלות N / M" (click = next unanswered) |
| Reports to markup (28/09, 29/09) | Doors, all ending in a GitHub issue on the skill's repository (`ISSUE_REPO` in `lib/issue.mjs`), and none of them in the right-click menu: there it competed with "comment" on every click and the user could not tell the two apart (user, 29/09). A report is about markup in general and is never tied to a place on the page. The doors: a muted button at the bottom of the table of contents (sticky, above a divider; hidden on read-only versions), which opens the compose card as a small fixed box next to the button; the same button in the help popover ("?" in the top bar, the door at every width, since the TOC hides below 1100px); and a link beside the version on the home page, which opens an inline form. One label everywhere: "Report a bug or idea to markup". The compose card in report mode is the same draft card: its heading, then the line saying the report is about markup in general (under the heading, not above it), type chips (bug / feature / question / other, bug first), a note on what happens next, and "Open on GitHub directly" beside the buttons, which opens GitHub's new-issue form prefilled (first line = title, text + environment = body, cut below a 7000-character URL). Sent, it is an ordinary thread with `kind: 'issue'`, `issueType`, `ua`: an issue glyph (ring with a dot) before the title, and `#<number>` linking to GitHub once the agent filed it. The agent path goes through the wake button like any comment; the home page belongs to no session, so there "Copy for the agent" copies `/markup issue <type>: <title>` plus the description. The agent always posts a draft and files only after the user approves (user, 28/09) |
| Help (29/09) | "?" in the top bar, before the theme button: a popover with how the page works (comment, send, questions, the agent button, the browser menu), the report door and the markup version. Opening it closes the first-visit tip for good (it says the same). Esc or a click outside closes it |
| Project identity (H#77, 31/08) | The top bar background is a faint tint of a hue derived from the project path (`fnv1a % 360`, stable per project, light and dark variants) so parallel projects differ at a glance. When the project root has an icon (`favicon.*`, `logo.*`, also under `public/`, `static/`, `app/`, `src/`, `assets/`, `docs/`) the server serves it at `/project-icon`; it replaces the ⌂ glyph next to the project name (40px, so it fills the 56px bar without growing it; 28/09), becomes the tab favicon, and heads the home page at 112px beside the project name. No icon → glyph and no favicon, tint still applies |
| Direction and language (H#72, 30/08) | `publish` detects the script of the content: Hebrew → `he`, Arabic → `ar`, Persian → `fa` (Arabic script with پ چ ژ گ ی), other RTL scripts → `rtl`, Latin → `en`; `--lang` overrides the code and `--dir rtl\|ltr` overrides the direction (`meta.textDir`; `meta.dir` is always the directory name). `dir` on `<html>` comes from the language's script; UI strings are Hebrew for `he` and English otherwise (no other translations yet). No direction toggle in the UI: direction belongs to the content |
| Shared preferences (H#73, 30/08) | `~/.markup/prefs.json`, served by every project server as `GET/PUT /api/prefs` (PUT merges). Holds the section defaults of the comments list (`secDefault`: which status sections show their cards) and whether the comments panel is folded (`panelCollapsed`); the page reads its localStorage cache first, applies the server value when it arrives, and writes both on every change. Mode and theme are still per browser origin (localStorage) |
| Dark theme (H#59, 30/08) | System preference by default; the ☾/☀ button in the top bar stores `markup:theme` (`dark` / `light`) and reloads (mermaid, Chart.js and highlight.js are initialized once per load). Every color in `plan.css` is a token: hand-picked base tokens in `:root`, plus `--c-<hex>` auto tokens for every literal the file had, flipped in lightness for dark (`dark.py` did the conversion; new colors go in as tokens, never literals — `@media print` stays light and literal). `plan.js` switches the heat scales (`SEQ`, `RG`, `PAPER`), Chart.js text/grid colors, mermaid `theme: dark` and the highlight.js stylesheet by `DARK` |
| What-if (H#66c, 30/08) | `.whatif` blocks: `[data-var]` inputs → variables (plus `data-vars` constants on the block), `[data-out]` echoes, `[data-calc]` evaluates with `Function(vars, Math)`, charts inside the block whose dataset values are strings are re-evaluated and `chart.update()`d on every `input` event. Formats ₪ $ € % 0 0.0. Print hides range sliders, keeps the values |
| Update balloon (V5, 28/09; chip 29/09) | When `GET /api/update` says a newer release exists and it was not dismissed, a chip "עדכון X" / "Update X" (`.upd-chip`) leads the top bar's actions; the card (`.upd-balloon`) opens under it only on a click and closes on a click elsewhere, because a card that opened by itself covered the text on every load (review 29/09). The card: "גרסה חדשה של markup: X", the installed version, "מה חדש" (the release notes, collapsed) and two buttons. The primary button depends on the install: `clean` → "שדרג" (`POST /api/upgrade`, then the page waits for a new `startedAt` from `/api/ping` and reloads); `modified` → "שדרג עם הסוכן" plus the list of changed files (a wake of kind `upgrade`; the agent status chip follows it; with no listener the command `/markup upgrade` goes to the clipboard, like the wake button); `dev` → the `git pull` command to copy. "לא עכשיו" dismisses that version (`~/.markup/update.json`). Read once per page load; never on an old version (read-only) view; hidden in print. The home page shows the same card, with the agent path as a command to copy |
| Extensions (V9, 28/09) | `template.html` carries `{{EXT_HEAD}}` (after `plan.css`), `{{EXT_VENDOR}}` (before `plan.js`) and `{{EXT_SCRIPTS}}` (after it), filled from `~/.markup/ext/` on every page load and served under `/_ext/`. `window.markup` (defined at the top of `plan.js`, so a later error cannot remove it) is the whole extension API: `register({ name, selector, init })`, `lang`, `plan`, `dark`, `readonly`. Keep it backward compatible; anything else in `plan.js` is internal |
| Print (R17, 30/08) | A4 with 16/14/18mm margins; header = the plan title, footer = project · date (both filled by the server into a `<style>` in `template.html`, since `@page` cannot read the DOM) and "n / N"; headings never end a page; tables, figures, cards, questions, code, steps never split; every tab panel prints with its tab label above it; `details` print open; picks print as ✓ lines without controls, empty free-text boxes hidden; mermaid capped at one page height; a diagram that portrait A4 (688px) would shrink below 75% of its natural width gets a landscape page of its own (`.mm-wide`, `@page wide`), together with the heading right above it, since its labels printed at ~5pt (29/09). Verified with `Page.printToPDF` in the automation Chrome. Also: top bar, panel, floats, TOC, copy buttons and filter boxes hidden; table headers repeat; external links print their URL; sticky headers reset. Tables shrink to fit the paper: 12px type, tight padding, headers and cells may wrap (`th` is nowrap on screen, and one long header can push a column past the page), long words break, a scrolling wrap stops clipping; only the ✓ ~ ✗ mark, sparklines, deltas, ranks and badges stay on one line (28/08). Comment highlights (`mark.c-quote`) and anchor bars (`.has-c`) do not print. Review 29/09: code blocks wrap (`pre-wrap`) instead of being cut at the page edge; cells break long words only when they overflow (`break-word`, `<code>` alone may break anywhere), since `anywhere` let a Hebrew table print one letter per line; the sort arrows do not print |

## Comments panel and floating cards

| Area | Convention |
| --- | --- |
| Comments panel | Panel mode: a fixed, draggable, resizable panel whose column is reserved while it is open (Layout). Open/closed state is the user's: one choice for every page and project (29/09; per plan, every new page opened folded), kept in localStorage `markup:panel-collapsed` and in the shared prefs (`panelCollapsed`), the server value winning when it arrives unless the user already clicked in that load; posting a comment never opens it. Nothing saved yet: open when the window is ≥1500px, folded below that. The bottom sheet (<900px) always starts closed and its open/close is not saved. With no comments the list shows how to make one ("Select text or right-click…"), not empty status sections |
| Starting a comment (28/09) | Three doors into one flow (`buildPending` → `openCompose`): right-click (menu first, showing the `C` shortcut and a line "Shift + right-click: browser menu", the one moment the user misses the native menu; 29/09), a "Comment" pill under the end of a selection inside the content (hidden while typing, while a compose box is open, or when the selection is scrolled off screen), and the `C` key (the selection, else the block under the pointer; never while typing). A first-visit tip in the bottom inline-end corner says how (touch devices: select text), until the page has a comment or the user closes it (`markup:tip-comment`, global). Centred it sat on the first table, and a phone squeezed it to half the width (29/09). While the compose box is open the selected words stay marked in the draft color (CSS Custom Highlight `markup-draft`): focus moves into the box and the browser drops the selection |
| Thread order | Oldest first, so they are handled in the order raised |
| Thread card | Header order from the inline-start corner: `#n` pill, "−" hide (floating only), fold chevron (▾/▸), title, trash. Short agent-written title (`# title` first line of the reply file); the fold collapses to the title line; delete is dimmed until hover, away from Reply |
| Revealing one card | A badge click or a side-list click shows that one card even when the filter hides its status; it never switches the filter (that surfaced every hidden card at once) |
| Status | One control at the bottom after the last message: the current status as a chip; clicking it opens a menu of three chips with soft status backgrounds (never colored text on a plain row). `closed` = "nothing to add", never "ignore" — `comments` surfaces unread closed threads once |
| Filters | Panel mode: the second row of the sticky panel head, directly above the threads (H#67, 30/08), never scrolling away with them; each status filter, and the status dropdown, carries its status color softly (amber open, blue waiting, gray closed; tinted at rest, solid when selected). Floating mode: no filter — the side list is sectioned by status, each section with an eye toggle (see "Section defaults") |
| Section defaults (floating mode) | Each status section has a default, shown (eye) or hidden (eye with a slash), stored per plan (`float-secdef`; initial: waiting and open shown, closed hidden). It applies to a card when it is created or arrives in that status. "−" on a card or a click on its row in the list overrides the default for that card (`float-override`) until its status changes again (`float-laststatus` detects the change on poll and drops the override). Flipping the eye applies the new default to the whole section: overrides there are dropped. There is no show-all / hide-all any more |
| Editing | Ctrl+Enter saves a new reply and an in-place edit alike |
| Section links | `[[#id]]` / `[[#id\|label]]` in agent replies render as jump-and-flash links; unknown ids fall back to text. Agent messages also render `code`, **bold**, `[label](https://…)` links and `- ` bullets (`mdLite`, 29/09: agents write markdown by habit, and raw backticks read as noise); user messages show as typed |
| Floating cards | Over the text (Layout): header 32px below the `#n` badge (`CARD_DROP`; 29/09: level with it, the connector ran flat along the text line and read as strikethrough, and the card hid the end of the commented line), ~48px past the far edge of the whole anchored block (clamped inside the page, so a full-width block gets its card over its own end), sliding at most ~140px to clear the card above, otherwise overlapping (stepped down one header so titles stay visible, later on top). Compact by default (340px wide, natural height capped at 340px with an inner scroll), resizable from the bottom corner to any size with our own handle (native CSS `resize` grows the wrong way in RTL) — no maximum; size remembered per thread. A card keeps its inner scroll across re-renders, and scrolls to the newest message when one arrives and on the first render of a `waiting` card: capped at 340px the answer was the part cut off (29/09). The title may take two lines (six header controls left ~16 characters on one). The clicked or jumped-to card is `focused`: fully opaque whatever its status |
| Delete control | A trash-can icon, never an "x" — an x reads as "close", and closing is a status |
| Badge placement | A comment made on a text selection carries its `#n` badge on the highlighted words themselves (`mark.c-quote`), not on the corner of the enclosing block; only block-level comments (no quote, or a quote that could not be re-found) sit on the block corner. The connector lands on that badge |
| Attachments | Compose and reply boxes take files: a paperclip button (file picker) and clipboard paste (Ctrl+V of an image) into the textarea. Sent as data URLs in the JSON body, saved by the server under `.markup/<dir>/assets/` with an ASCII-safe name, kept on the message as `{name, file, type, size}`, shown inline (images as previews, other files as links), 8MB per file. Served with `Content-Security-Policy: sandbox`, so a script inside an html or svg attachment never runs. `comments` prints `  attachment: <absolute path>` under the message |
| Jump to anchor | The `#n` pill in the thread header (same design as the page badge, status color) — clicking it jumps to the anchor. There is no separate "jump" button |
| Connectors (floating mode) | One straight 1px segment from the card's edge facing the anchor, level with its `#n`, to the `#n` badge on the anchored block (slightly diagonal, since the card sits `CARD_DROP` lower) (28/09: from the `#n` itself the line ran across the card's own title and read as strikethrough; a card that sits over its anchor still starts at the `#n`). Every card draws its line (cards sit next to their anchors, so the lines are short). Drawn above the ordinary cards (so the end is never hidden by a border) but below the focused card (so a line to another card never crosses the one being read): ordinary cards carry inline z-index 6..19 by recency, the lines layer is 20, the focused card 22; `.floats` has no z-index of its own. No elbows, no curves, no edge-picking |
| Maximize | A ▢ button next to "−" in a floating card header: 80% of the content area (10% margin all round, between the docked panel and the TOC), focused; ❐ restores the previous place and size. Session-only |
| Reveal flash | Revealing a card tints it strongly and fades to the paper color — never through transparency |
| Default mode | Floating (anchored) is the default; an explicit switch to the panel is remembered globally. Narrow windows run panel mode without changing it (Narrow windows) |
| Re-anchoring (28/09) | A block whose text changed is re-found by exact text, then by prefix, then by word overlap (Dice ≥ 0.6 over the words, +0.1 in the same section) among blocks of the same tag, so a small edit keeps the comment on its cell instead of sending it up to the table. The card says where it went in words: "Moved to: table "…"", "Was on: cell "…"" (kind + snippet), never `<td>` |
| Mermaid look (28/09) | Theme `base` with the page's palette (slate nodes, pale-yellow notes, a dark variant). Labels take their direction from their own text (`unicode-bidi: plaintext`), so a Hebrew label with "מ-GitHub" keeps its hyphen. Quotes after `participant X as` are stripped before rendering (they print literally). Dark mode rewrites `classDef` / `style` colors before rendering: a pale fill becomes a dark shade of the same hue, a dark stroke or text color a light one, so the guide's pale fills stay readable (29/09). A wide diagram keeps at least 75% of its natural width (`--mm-min`) and scrolls sideways past that, fading on the side that has more: fitted to a narrow column its labels went down to ~9px (29/09). A comment on a diagram names it by its figcaption, else its source (`data-mm-text`), never the rendered labels in paint order |
| Home page (28/09) | Language of most of the project's pages (the browser's with none), its own direction, dark mode, the project icon only when one exists, the markup logo and version at the bottom. Counts only when non-zero; delete shows on hover or focus of its row, with a confirm that names the page. Dates in the same form as the page's version menu, `DD/MM/YYYY HH:MM` (it followed the browser and showed 09/29 beside the page's 29/09; then he-IL wrote 28.09.2026). The list sits in `<main>`. A browser opening a page that no longer exists is sent to `/?gone=<dir>`, which names it in a note above the list (it got raw JSON, 29/09) |
| Dragged positions | Stored as an offset from the anchor badge (`{dx, dy}` per thread), never as page coordinates, so a republish that adds sections above keeps every card next to its anchor; capped at one viewport height either way. Legacy absolute entries are converted once and dropped when already far |
| Side list order (floating mode) | "טיוטות" first, shown only while a draft exists (compose draft and reply drafts; a click reopens the box with the text), then "ממתין לי" (the user's to-do list), then "ממתין לסוכן", then closed. The list never depends on the status filter, so it is never empty while threads exist. An empty status section keeps its head (its eye is the default for cards that arrive later), dimmed, with no "No comments" line; the count is the total, or "shown/total" only when some cards are hidden (29/09) |
| Drafts | Unsent text survives a reload: reply drafts per thread (the reply box reopens with the text), and one compose draft with its anchor (a bottom notice "הערה שלא נשלחה" offers open / discard; open re-anchors and reopens the compose card). Kept in localStorage per plan; sending clears it; the server and `comments` never see drafts. An open edit of a user message is a draft too (open = drafted, so it survives re-render and reload). Unsent attachments (compose and reply boxes) live in IndexedDB (`markup` / `files`, key `<plan>|compose` or `<plan>|reply:<id>`); closing the compose box by a click outside, Esc, cancel or "−" keeps text and files, only send and the trash discard them. A re-render keeps focus, caret and scroll of the reply or edit box being typed in (the page re-renders on every poll that changed something) |
| Compose card | The new-comment box is a thread card rendered by the same `threadHtml` with status `draft` (purple: `--c-draft`, the `+` pill, the card edge and the connector), so it carries the same header: `+` pill (drag), "−" (hide, the draft stays and is listed under "טיוטות"), ▢ maximize/restore, ▾ fold, title, trash (discard the draft); body is the textarea, attachments and send / cancel / attach instead of messages, reply and status. Panel mode hides the header and handle by CSS and keeps the small fixed box. Elements the draft does not need are conditional inside the renderer, never a second component. Titled "New comment" (the menu's "Add comment / question" was cut off in the header). It opens where the user pointed: under the end of the selected words with its `+` at their end, else at the pointer (right-click, `C`), above them when the window has no room below (user, 29/09: placed past the far edge of the whole block, it opened a table row's width away from the mouse). While it sits against the words (within 24px, overlapping them sideways) it draws no connector; dragged away, the line returns. ## Floating mode, in prose

The "מעוגן | פאנל" pair at the head of the comments panel (`#modeSeg`, H#53 30/08; names per G6: "מעוגן" = cards next to their anchors, "פאנל" = everything in one panel) switches the page to floating ("מעוגן") mode, remembered in `localStorage` (global, all plans). The top bar keeps only versions, the context meter, the question counter, the agent status and "הערות (N)". The head's first row is "הערות" at the inline-start and the pair + the fold button (») at the inline-end; the fold (H#67) always lands in anchored mode with the panel as a thin strip, and opening the panel again (strip click or the "הערות (N)" button) restores the mode that was on before the fold (`localStorage` `markup:mode-before-fold`). In the collapsed strip the pair, the fold button and the filters are hidden. In that mode every thread is its own card in the cards column on the inline-end side of the text (left in RTL), level with its anchor; the focused or hovered card is joined to it by one straight 1px line in the status color. When the window has no room for the column (Layout), staying next to the anchor wins over not overlapping: a card slides down a little to clear the previous one when that keeps it near its anchor, otherwise it overlaps (cascaded sideways, later on top; a click brings a card to the front). The user can drag any card by its header (position remembered per plan) and double-click the header to snap it back. "−" hides a card so it is listed only in the side panel. In floating mode the panel is docked as a fixed column on the inline-end side, collapsible to a thin full-height strip (click the strip to reopen), and it shows a compact one-line-per-thread list grouped into foldable sections by status. Everything else — fold, reply, edit, status dropdown, delete, `[[#id]]` links — is identical in both modes, and `comments.json` does not know which mode the user is in.
